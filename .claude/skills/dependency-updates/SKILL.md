# Dependency updates

Upgrades go to the latest stable only; bumping a 0.x peer range is a major (root `CLAUDE.md`, "Semantic Versioning").

## pnpm and Dependabot

- **What Dependabot opens (`.github/dependabot.yml`):** one grouped PR with the npm security fixes it makes, and one weekly grouped PR for the GitHub Actions in `.github/workflows`. npm version updates are off (`open-pull-requests-limit: 0`). Security PRs always target the default branch (`dev`). **It makes fixes for direct dependencies only:** every Dependabot PR since the move to pnpm (#267 to #648) bumped a direct dependency, and none was opened for the 12 packages that were only transitive among the alerts #879 closed (body-parser, qs, undici and nine more), not even for the nine whose fix was inside the parent's range. Transitive alerts in `pnpm-lock.yaml`, and any whose parent at its latest release still asks for the vulnerable major (an override, as tinypool and webpack-dev-middleware on #879), need a sweep by hand as below; Dependabot closes its own PRs once their alerts are gone.
- **A sweep by hand checks itself against the alerts:** test every open alert's `vulnerable_version_range` against every version of that package in the new `pnpm-lock.yaml` with `semver.satisfies` (0 left = done), and run the same test over the fixed alerts. When an override forces a major on a tool, run the code path that loads it: the website's normal build never starts tinypool (`future.v4: true` turns on `faster.ssgWorkerThreads`, but the pool falls back to the current thread below 100 pages per thread, and the site has about 60); `DOCUSAURUS_SSG_WORKER_THREAD_COUNT=4 docusaurus build` does (the code comment's `DOCUSAURUS_SSG_WORKER_THREADS` is wrong; `DOCUSAURUS_PERF_LOGGER=true` prints `SSG Worker N` lines when the pool runs). webpack-dev-middleware runs only under `storybook dev`, not `storybook build`.
- **Transitive Dependabot alerts**: try `pnpm update -r <pkg>...` first (refreshes the lockfile within parents' existing ranges) before adding a `pnpm.overrides` entry — most alerts are just stale lockfile patches the parent range already allows. Reserve overrides for a version an intermediary pins _below_ the fix (forced; may break upstream's tested range, e.g. js-yaml 3.x via gray-matter).
- **`pnpm update -r <names>` silently degrades to direct-deps-only** (pnpm 8) if you pass `--depth Infinity` OR if any named package is a direct dep somewhere in the workspace (e.g. `uuid`, `esbuild` in browser) — the transitive names in the same call are then skipped with no error. Keep direct deps out of the list and confirm by grepping `pnpm-lock.yaml` for the new versions.
- **Before removing a `pnpm.overrides` entry, check the FIXED alert history, not just open alerts** — `gh api --paginate 'repos/naomiaro/waveform-playlist/dependabot/alerts?state=fixed&per_page=100'` and test each `vulnerable_version_range` against the new lockfile; a dropped override silently reopens old alerts (serialize-javascript and uuid did, 2026-10-06). Scope a new selector to the parents' declared spec (`esbuild@^0.27.0`, not `esbuild@<0.28.1`) so unaffected consumers aren't dragged along (vite 6's `esbuild ^0.25` was one, until #879 removed vite 6). `pnpm audit` reads the npm advisory DB, which runs ahead of this repo's Dependabot list — use it to find in-range fixes worth taking early.
- **`dependencies`→`peerDependencies` move churns the lockfile** — it changes pnpm hoisting and can re-resolve unrelated transitive deps (e.g. `@types/react` 19→18 from a workspace `^18` vs react-19 mismatch). A pristine-base `pnpm install` no-op confirms the move (not pre-existing drift) is the cause; `--frozen-lockfile` still passes if internally consistent.
- **Adding ANY dependency re-resolves unrelated transitive versions on this lockfile** (2026-11-23, #891): `pnpm add -Dw semver@^7.8.3`, and a hand-edited `package.json` line plus `pnpm install`, both also moved babel's `semver` 6.3.1 → 6.3.2 and `tslib` 2.8.1 → 2.9.1 (37 lockfile lines for one new entry). Read `git diff pnpm-lock.yaml` before committing a new dependency; for a few lines of build-script logic, writing them was the smaller change (`scripts/build/install-specs.mjs`, `satisfiesFloors`).

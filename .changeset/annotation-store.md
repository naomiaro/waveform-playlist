The annotations have one owner, an annotation store (#867). Before, the library built each annotation change from the annotations of the last render and handed the whole array back through `onAnnotationsChange`, so two changes in one tick lost one (two `setAnnotations(fn)` calls, or an annotation the app added in the same tick as a drag release).

core: new `createAnnotationStore(initial?, { beforeChange? })` and the types `AnnotationStore` and `AnnotationStoreOptions`. The store has `getAnnotations()` (the same array until a change), `subscribe(listener)` (returns the unsubscribe function), `set(list)` and `update(fn)`; both apply before they return, so two updates in one tick both land, and an `update` that returns `current` notifies nobody. Every list it is given (the initial list, `set`, `update`'s result, `beforeChange`'s result) must have finite numeric `start` and `end` and unique ids, in every build; otherwise it throws a `TypeError` and keeps its value. `beforeChange(next, current)` returns the list to store: `next` accepts, `current` refuses, another list adjusts; it is not called for the initial list. In a development build (`process.env.NODE_ENV` set and not `'production'`) the list, each annotation and its `lines` are frozen. A subscriber that throws is warned about; the others are still told. New `applyAnnotationBounds(current, changes)` and its `AnnotationBoundsChange` type: writes `start`/`end` by id, keeps everything else, skips unknown ids, returns `current` when nothing changes. `AnnotationFormat.serialize` and `updateAnnotationBoundaries` accept `readonly` lists; an `AnnotationFormat` an app implements must now take `readonly AnnotationData[]` in `serialize` (with `strictFunctionTypes`, one typed `AnnotationData[]` no longer compiles).

browser: both providers take `annotationStore?: AnnotationStore`; without it there are no annotations. New hooks `useCreateAnnotationStore(init?, options?)` (one store per component instance; `init` read once, a throw goes to the error boundary; the latest committed render's `beforeChange` is called) and `useStoredAnnotations(store)` (re-renders on a change; works above the provider). Removed: `onAnnotationsChange` on both providers, the `annotations` field of `annotationList` (which keeps `editable`, `linkEndpoints` and `isContinuousPlay`), and `usePlaybackControls().setAnnotations`; `usePlaybackControls().annotationStore` (the prop, or `undefined`) is new, and the controls value changes identity when that prop does. `useAnnotationDragHandlers` and `useAnnotationKeyboardControls` take `store` in place of `annotations` and `onAnnotationsChange`, and do nothing without one. `useAnnotations().annotations` is `readonly AnnotationData[]`; `useAnnotationsWithPreview` takes and returns `readonly`. An edge drag keeps the bounds of every annotation it has touched and works out each move over the store's current list with them on top, so a neighbour the app moved during the drag collides where it is now. With the preview, the release writes only those `start`/`end`, by id, onto the store's list as it is then (an annotation added or edited during the drag stays), and the boxes and the list show the store's current list with the drag's bounds on top; without it every move writes them and Escape writes their drag-start bounds back. The drag ends, writing nothing more, when its annotation is removed from the store, when the provider is given another store, or when the component unmounts. The boundary keys find the active annotation by id when the key is pressed; a key at a clamp, and a text blur with unchanged text, tell no subscriber. Invalid annotations no longer log a development error and show nothing: the store throws.

annotations: `AnnotationText` takes `store?: AnnotationStore`; `onAnnotationUpdate` is removed. Text, id and action edits call `store.update` and find their annotation by id in the store's current list; without `store` the list is read-only (no editable field, no action button, whatever `editable` says). The id field refuses an id another annotation has, as it refused an empty one, and a field whose edit was not stored shows the stored value again. An action gets copies (the array, and each annotation with its `lines`) and the position in the store's list; the `AnnotationAction` type is unchanged. `annotations` accepts a `readonly` list.

See the upgrade guide.

`<daw-editor>` on the arrangement, as close to the native DOM as possible (#848).

- `editor.arrangement`: the arrangement the editor plays. By default the editor's own, whose content the `<daw-track>` children declare. Set an arrangement (`createArrangement()` from `@waveform-playlist/engine`) to play it alone, like `video.srcObject`: the children are not added to it and are detached while it is set; `null` goes back to the own arrangement with what it held. A swap keeps the adapter (playback stops, a new engine is built with it), disposes the effects chains of tracks the new arrangement does not hold, and fires `daw-track-ready` for each of its tracks. A value that is not an arrangement throws a `TypeError`; a swap during a take is refused with a warning. The editor never disposes or clears an arrangement it was handed.
- `<daw-track>` and `<daw-clip>` behave like `<input>`: the attributes are the page's declaration and the editor never writes them; the properties are live. `trackEl.name`, `volume`, `pan`, `muted` (the stored mute) and `soloed`, and `clipEl.start`, `duration`, `offset`, `gain`, `name` and the MIDI fields read the arrangement while it holds the element's id, and setting one (or changing its attribute) is a request to it, one undo step; a value it already holds changes nothing. A property set before the track enters is the value it enters with. New: `trackEl.index`, the track's position in the arrangement (`-1` when not in it).
- A `<daw-clip>` moved into another `<daw-track>` (`appendChild` or `moveBefore()`) moves its clip there, one undo step; before, the new track took the clip and the old one kept it. A track of the other kind refuses it, with `daw-clip-error`, and nothing changes. Into a track still waiting to enter, the clip moves when that track enters (one undo step with its arrival); into a detached track, the move is refused. The editor moves no element, also on an Undo or Redo of a move: a `<daw-clip>` is linked to its clip by id wherever it sits. Removing a `<daw-track>` removes its track and every clip its children declared, one undo step. `<daw-track>` and `<daw-clip>` define `connectedMoveCallback`, so a `moveBefore()` keeps their state.
- Detached elements: an element whose id left the arrangement (an Undo of its arrival, a removal made on the arrangement, a refusal) or that waits while a handed-in arrangement is set is detached. It is not drawn, not in `editor.tracks`, its properties read its declaration, a change on it changes nothing in the arrangement and logs a warning (an attribute change still updates the declaration), and it carries the custom state `detached` (`daw-track:state(detached)`, `el.matches(':state(detached)')`). A Redo of its arrival makes it live again. A `<daw-clip>` or `<daw-track>` the page removes while an Undo has taken it, or its track, out of the arrangement is gone for good (no Redo brings it back); a `<daw-clip>` added to a detached `<daw-track>` never enters, warns and shows `:state(detached)`.
- A drag shows its change on screen and changes the arrangement once, on release (a clip move used to write every pointer move inside a transaction). A change to the arrangement made elsewhere during a drag (`arrangement.undo()`, `reorderTrack`, `removeTrack` from app code or an agent) cancels the drag when it changed what is dragged; the change goes through. A track that enters during a drag is an undo step of its own (it used to wait for the drag to end); it cancels a track drag (the track count changed), and a clip drag goes on.
- A split keeps the clip's id on its left half (`daw-clip-split`: `leftClipId` is `originalClipId`), so a `<daw-clip>` follows its left half.

- Cancellation: `addTrack(config, options?)`, `addClip(trackId, config, options?)` and `loadFiles(files, options?)` take `options.signal` (`EditorCallOptions`, exported). An abort rejects with the signal's `reason` (a `DOMException` named `AbortError` by default) and takes out for good what the call added: a track that has not entered never enters, a clip that has not loaded is removed, the tracks `loadFiles` added are removed. A signal already aborted rejects at once and adds nothing. `loadMidi`'s `signal` now also ends the `addTrack` waits it started. A swap of `editor.arrangement` rejects a pending `addClip()` with an `AbortError` (its loading clip stays in the arrangement swapped out), ends `loadFiles()` waits as at a disconnect, and aborts peaks fetches. `<daw-player>` aborts its peaks fetch on a new `peaks-src` and on disconnect, and fetches again on reconnect. The editor's and the elements' listeners are registered with an `AbortSignal` per connection.

**Upgrading:**

- `editor.addTrack(config)` creates no `<daw-track>` element, and `editor.addClip(trackId, config)` creates no `<daw-clip>`: the track or clip is added to the arrangement. `addClip` works on every track now (it used to require an element). Find: code that looks for the element `addTrack` / `addClip` made (`querySelector('daw-track')` after `addTrack`). Replace with: the returned id, `editor.tracks`, or `editor.arrangement`.
- `editor.updateTrack()` and `editor.updateClip()` write no element: the change goes to the arrangement, the element's properties show it, its attributes keep what the page wrote. Find: reads of `trackEl.getAttribute('volume')` (or `name`, `muted`) or `clipEl.getAttribute('start')` expecting the new value. Replace with: the property (`trackEl.volume`, `clipEl.start`) or `editor.tracks`. For `render-mode` and `spectrogramConfig`, which are declaration-only properties, read `editor.tracks[i].renderMode` / `.spectrogramConfig`. `fadeIn` / `fadeOut` / `fadeType` passed to `updateClip` change nothing (the arrangement holds no fades yet; they used to be written to the `<daw-clip>`).
- `loadMidi()`'s cleanup after a failed track removes the tracks it added with no undo step (each removal was one). Find: code that called `editor.undo()` after a failed `loadMidi()` to bring tracks back. Replace with: nothing to undo: the editor is as it was before the call.
- `editor.reorderTrack(trackId, toIndex)` takes an index in the arrangement's order, every track counted (those with no element too); it used to count `<daw-track>` elements. It moves no element, and an Undo of a reorder moves no element either. Find: an index computed from `querySelectorAll('daw-track')`. Replace with: `trackEl.index`, or the position in `editor.tracks`.
- The editor no longer moves `<daw-track>` elements to follow the arrangement's order, or writes the reflected `kind` attribute back after a refused change: `trackEl.kind` reads the kind the track entered with, and the attribute keeps what the page wrote. `<daw-editor>`, `<daw-track-controls>`, `<daw-player>` and `<daw-annotation-list>` honour the `hidden` attribute (`:host([hidden]) { display: none }`; their `display` used to override it). A page that reads the track order from its children reads `editor.tracks` (or each `trackEl.index`).
- A rename (`name` attribute or property, `updateTrack({ name })`) is an undo step, and the name shown is the arrangement's.
- A `<daw-clip>` removed from the page while the editor is detached has its clip removed when the editor is inserted again.

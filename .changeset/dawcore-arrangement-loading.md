dawcore: `<daw-editor>` loads through its arrangement (#848).

- The editor owns an arrangement (`createArrangement()` from `@waveform-playlist/engine`) from the moment it is created, and builds its engine on it as soon as it is connected with an `editor.adapter`. `@waveform-playlist/engine` is imported normally (it was loaded with a dynamic import on the first track load).
- A `<daw-track>` enters the arrangement as soon as there is an engine, at its place in the DOM, before its audio has loaded: each audio `<daw-clip>` becomes a loading clip, and the arrangement fetches and decodes it. A `<daw-track>` inserted between two others later lands at its DOM position. Tracks that connect before `editor.adapter` is set wait for it (they used to fail), and a track that connects during a clip or track drag enters when the drag ends.
- Loading no longer clears the undo history. A `<daw-track>` element of the page that enters while the history is empty is not an undo step, so Undo right after load removes nothing; one the page adds once the history has steps, a track from `editor.addTrack()` or `loadMidi()`, and a file drop are one undo step each. A control moved while a track loads is an undo step like any other.
- A track whose audio failed stays in the editor, like a broken `<img>`: `daw-clip-error` and `daw-track-error` fire, its clip is drawn failed where its length is known (a `duration`, or `peaks-src`; `--daw-clip-failed-color`), and `editor.retryTrack(trackId)` loads it again (`daw-track-ready` follows). A clip still loading is drawn dimmed where its length is known (`--daw-placeholder-clip-opacity`), with its `.dat` peaks when `peaks-src` gives them.
- `daw-track-ready` fires when the track's audio has loaded (its peaks are drawn a moment later; it used to wait for them), and again each time the track has loaded again after loading or failing (a clip added later, a retry). `daw-clip-ready` fires for every clip whose audio has loaded (it fired for an appended clip only). For a track with nothing to fetch, or whose audio is already loaded, these events fire before `addTrack()` resolves.
- `editor.addClip()` rejects when its clip or its track is removed, or an Undo takes the clip out, before the clip's audio loads, and at once for a track an Undo took out; it used to hang. These rejections send no `daw-clip-error`.
- `editor.tracks` lists the tracks in the arrangement's order (was: the order they registered in), then those waiting for an adapter; a track an Undo took out is not listed until a Redo brings it back. `editor.duration` counts a loading clip whose length is known.
- A clip whose `duration` runs past the end of its audio is cut to the end, with a console warning (it was drawn and played to the declared length, silent past the audio), as in the React editor.
- A file drop (`loadFiles`) adds a track with no `<daw-track>` element: its clip's source is the `File`. A file that cannot be loaded is removed with no undo step. When the editor is removed from the document during `loadFiles()`, the call resolves: a file whose track has entered and is still loading is kept and reported in `loaded` (it loads after a reparent; if it fails then, it stays as a failed track), a file still waiting to enter and the files not started are reported in `failed`.

Upgrading:

- `@dawcore/components` needs `@waveform-playlist/engine` 14.0.0-next.3 or later (peer `>=14.0.0-next.3`; it was `>=13.5.0 || >=14.0.0-0`): it imports `createArrangement`, which engine 13 does not have, and passes `addTrack`'s `index`, which earlier 14 prereleases ignore (a track inserted between two others would land at the end). Install the engine's 14 line (`@next` until its release).
- `editor.addTrack(config)` resolves with the track id (a string) once the track has entered the editor, not with the `<daw-track>` element once its audio has loaded, and it no longer rejects when the audio fails or every clip was refused. Find: `const t = await editor.addTrack(…)` followed by `t.trackId` (or `(await editor.addTrack(…)).trackId`). Replace with: `const trackId = await editor.addTrack(…)`. For the element, `[...editor.querySelectorAll('daw-track')].find((el) => el.trackId === trackId)`, or use the id-keyed editor methods (`updateTrack`, `removeTrack`, `addTrackEffect`). To follow loading, add the `daw-track-ready` / `daw-track-error` listener for that id BEFORE calling `addTrack`: for a track with nothing to fetch, or whose audio is already loaded, they fire before it resolves.
- Tracks an app adds with `editor.addTrack()` or `editor.loadMidi()` as the page's starting content are undo steps now (loading used to clear the history). Call `editor.engine.clearHistory()` after adding them if Undo right after load should remove nothing.
- `daw-track-ready` no longer waits for the peaks to be drawn and can fire more than once per track: code that ran once per track on it should keep track of the ids it has seen.
- `DawTrackErrorDetail.reason` is removed: a track removed, or an editor disconnected, while its audio loads no longer fires `daw-track-error` at all, so a filter on `reason` has nothing left to filter. Find: `detail.reason`. Replace with: nothing (delete the check).
- A track whose audio failed is no longer left out: remove it with `editor.removeTrack(trackId)` on `daw-track-error` if the app does not want it shown.
- A dropped file has no `<daw-track>` element: read dropped tracks from `editor.tracks` (or the ids `loadFiles()` resolves with), not from the editor's children.
- After `<daw-editor>` is removed from the document, `editor.adapter` is `null` (the engine disposed it) once an engine had been built: set a fresh adapter when the editor is inserted again. Its tracks, their mix and the undo history are kept.

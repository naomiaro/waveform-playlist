'@dawcore/transport': patch
---

The scheduler timer is now a Web Worker `setTimeout` loop (25 ms, `DEFAULT_TIMER_INTERVAL_MS`) instead of `requestAnimationFrame`. Browsers stop rAF and throttle main-thread timers in a hidden tab, which let the 200 ms lookahead run dry and playback go silent until the tab was shown again; Worker timers and message delivery keep their cadence in the background. One Blob-URL Worker lives for the `Timer`'s lifetime (`start`/`stop` are messages; `Transport.dispose()` terminates it via the new `Timer.dispose()`). Where no Worker can be created (Node/SSR, or a CSP without `worker-src blob:`) the Timer falls back to a main-thread `setTimeout` loop. `Timer` accepts `{ intervalMs }`. `NativePlayoutAdapter.init()`'s Safari warmup poll also moves from rAF to `setTimeout`, so `init()` can no longer hang in a hidden tab. Tests that drove the transport through `requestAnimationFrame` stubs should use `vi.useFakeTimers()` and `vi.advanceTimersByTime(DEFAULT_TIMER_INTERVAL_MS)`. `Transport` emits a new `ended` event when a bounded `play(start, end)` reaches its end (right after `stop`, so a handler may restart playback; never for a consumer stop), and `NativePlayoutAdapter` now implements the engine's `onPlaybackEnded` hook by forwarding it (a direct `adapter.transport.stop()` is not reported as completion), so bounded `play(start, end)` completion reaches the engine's `stop` event instead of depending on a consumer's rAF loop observing the end before the transport's tick. A Worker that fails after construction (error event) falls back to `setTimeout` instead of leaving the transport silent; the refusal is warned once per page; `start()` after `dispose()` is a warned no-op. A Worker that never delivers a first tick is abandoned by a watchdog; a transport tick that throws stops the transport (warned once) instead of retrying 40×/s; `play()`/`seek()` after `dispose()` are warned no-ops; `TransportOptions.timerIntervalMs` and the exported `DEFAULT_TIMER_INTERVAL_MS` are new; `NativePlayoutAdapter.init()` now rejects if the AudioContext closes during the warmup poll.

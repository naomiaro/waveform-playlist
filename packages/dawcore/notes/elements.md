# The elements

Notes of dawcore Package (`@dawcore/components`), moved out of the package's `CLAUDE.md`. Read before adding or changing an element, its attributes or properties, the track controls, the empty state or the spectrogram.

## Element Types

**Data elements (light DOM):**

- `<daw-clip>` — Declarative clip data (src, start, duration, offset, gain, fades). Auto-generated `clipId`. Since #848 PR 3 `start`, `duration`, `offset`, `gain`, `name`, `midiNotes`, `midiChannel` and `midiProgram` are live (`interactions/element-links.ts`): while the arrangement holds the clip they read it, and a set (or an attribute change) calls `editor._requestClipChange` synchronously, one undo step (a clip still loading changes its `LoadingClip`); otherwise they read the declaration. `daw-clip-update` still fires after a change; the editor does not listen to it.
- `<daw-track>` — Track data (name, volume, pan, pan law, muted, soloed). `pan-law` (#684) declares the law the track enters with (`mono` / `stereo`; `auto`, empty or none: the track's first decoded audio decides; anything else is not a declaration, one warning from `declaredPanLaw` in `utils/track-mix.ts`). The live `panLaw` property reads the arrangement's mixer value (`'auto'` until the track has audio) and the editor writes no attribute, so a law the first audio decided shows in the property only. A set of `'mono'` / `'stereo'` on an entered track is a request (`_writeMix` → `arrangement.setTrackPanLaw`, one undo step, in the track's task gesture with a pan set beside it); `'auto'` there is not sent (a decided track does not go back). The mix helpers that name the fields: `mixOfTrack`, `mixOfElement`, `pickMix`, `DEFAULT_TRACK_MIX`, `sameMix` and `loadedTrack` (`interactions/arrangement-view.ts`: the export reads the law from that view), `_writeMix` / `_writeMixFields`, both branches of `_updatePendingTrack`. Dispatches `daw-track-connected` on mount, `daw-track-update` `{ trackId, changed }` on property change (`changed`: the names from `TRACK_PROPS` that this Lit update changed; `DawTrackUpdateDetail`). Since #848 PR 3 `name`, `volume`, `pan`, `panLaw` (#684), `muted` (the stored mute) and `soloed` are live: while the arrangement holds the track they read it, and a set (or an attribute change) calls `editor._requestTrackChange` synchronously; mix sets on one track within one synchronous run (`_taskGestures` is cleared in a microtask) share a gesture id, so they are one undo step (#843), and a rename is a step of its own. The editor's `_onTrackUpdate` handles only `kind`, `renderMode`, `spectrogramConfig` and `src`. `trackEl.index` is the position in the arrangement (-1 when not there); a detached element carries `:state(detached)` and warns on a change. Track removal detected by editor's MutationObserver (not events — detached elements can't bubble).
- `<daw-annotation>` — Single annotation: reflected `start`/`end` (seconds, validated non-negative finite) ARE the source of truth for a seconds-based annotation, light-DOM text content is the label. Also has reflected `start-tick`/`end-tick` (optional, validated non-negative finite integers) — authoritative over `start`/`end` when BOTH are set (see "Dual-Timebase Annotations" gotcha below). `annotationId` = `id` attribute or a generated UUID. Dispatches `daw-annotation-connected` (deferred) and `daw-annotation-update` (on `start`/`end`/`start-tick`/`end-tick` change, not on mount).
- `<daw-annotation-track>` — Timeline row of `<daw-annotation>` children; owns ephemeral selection (`activeAnnotationId`) and the navigation/boundary-edit/keyboard API. `editable`/`link-endpoints`/`continuous-play`/`keyboard-controls` are reflected booleans. `box-label` (`'text'` default / `'id'` / `'none'`) controls the lane box's text — only affects the timeline lane, not `<daw-annotation-list>`. `name` (reflected string, default `''`) is the lane's display label rendered in the editor's controls-column spacer (mirrors `<daw-track name>`; empty = blank spacer). Dispatches `daw-annotation-track-connected`, `daw-annotation-select`.
- **Standalone view:** `<daw-annotation-list for="trackId">` — Shadow-DOM text panel; NOT a data element (renders a dual view of a `<daw-annotation-track>`'s children, doesn't own data). See "Annotation Elements" below for the full pattern.

**Annotation-specific gotchas:**

- **Slot text leak → data elements self-hide.** `<daw-editor>` has a bare `<slot>` for its light-DOM children (`<daw-track>`, `<daw-keyboard-shortcuts>`, `<daw-annotation-track>`). A `<daw-annotation>`'s text content is its label, not renderable page content — both `<daw-annotation>` and `<daw-annotation-track>` set `this.style.display = 'none'` in `connectedCallback()`, or their text would leak into the editor's rendered output through the slot. This is the same reason `<daw-clip>`/`<daw-track>` don't need it (they carry no free-text content).
- **Lit-ChildPart-vs-contenteditable imperative sync.** `<daw-annotation-list>`'s row text is set imperatively (`span.textContent = text`), never bound as a Lit expression. `contenteditable` mutates the span's DOM directly as the user types, which ejects lit-html's `ChildPart` marker comments at that position — a later Lit-driven re-render of the same row throws `"ChildPart has no parentNode"`. `shouldUpdate()` also refuses to re-render while `_editingId` is set. See `_syncRowText()` in `elements/daw-annotation-list.ts`.
- **Capture-phase keyboard priority.** `<daw-annotation-track keyboard-controls>` registers its `keydown` listener on `document` with `{capture: true}`, so it runs before `<daw-keyboard-shortcuts>`'s bubble-phase listener regardless of DOM position. A consumed key calls `e.stopImmediatePropagation()` (not `stopPropagation()`) — required because multiple annotation tracks each add their own capture listener to the same `document` node, and only `stopImmediatePropagation()` stops sibling listeners there. Net effect: a consumed key acts on the first-registered track only (DOM connection order); unconsumed keys (`Escape` with no selection, gated boundary-edit keys) fall through to siblings and to editor-level shortcuts.
- **`ANNOTATION_LANE_HEIGHT` constant** (`controllers/annotation-controller.ts`, value `32`) — a TS constant, not a CSS var, because the frozen-panes controls-column spacer and the beats-grid top offset (`AnnotationController.totalLaneHeight`) both need it in layout math, not just CSS.
- **Selection is ephemeral, broadcast via `daw-annotation-select`.** `activeAnnotationId` lives only on the `<daw-annotation-track>` instance (not reflected as an attribute, not stored on the `<daw-annotation>` elements) — it's UI state, not data. `<daw-annotation-list>` and the editor's lane both listen for `daw-annotation-select` on `document` to sync their active-row/active-box highlighting rather than polling the property.
- **`indefinite-playback` lifts the annotation end clamp.** Boundary writers (`AnnotationDragHandler`, `<daw-annotation-track>._moveBoundary`) read `editor._annotationClampDuration` (not `_duration` directly) — it's `Infinity` when `indefinite-playback` is set, else `_duration`. Temporal-mode `_totalWidth` also extends past `_duration` to `AnnotationController.maxAnnotationEndSeconds` so out-of-audio-range annotations stay reachable/scrollable regardless of `indefinite-playback` (beats mode is untouched — documented limitation).
- **Dual-timebase annotations (`startTick`/`endTick`, mirrors clip `startTick`).** `AnnotationData.startTick`/`endTick` (optional, `@waveform-playlist/core`) are authoritative when BOTH are set; `start`/`end` seconds become a derived cache. `AnnotationController.deriveSecondsCaches()` (`controllers/annotation-controller.ts`) sweeps every tick-based `<daw-annotation>` and writes the fresh `_ticksToSeconds()` result onto `start`/`end` — called on track registration (`handleTrackConnected`), on `daw-annotation-update`/`daw-annotation-select`/`daw-annotation-connected` (`_onDataChange`), and from `<daw-editor>`'s engine `statechange` handler whenever `engineState.bpm` differs from the last-seen value (`_lastAnnotationBpm`). **Write-only-on-change loop safety:** the sweep only assigns `el.start`/`el.end` when the computed value actually differs — a write fires `daw-annotation-update` → `_onDataChange` → the sweep runs again → values now equal → no write → the loop settles in exactly one extra pass (idempotent, not an infinite re-render). Boundary math (drag, `moveStartBoundary`/`moveEndBoundary`) runs in tick space via `tickSpaceData`/`applyTickBoundaryResults` in `elements/daw-annotation-track.ts` — `applyTickBoundaryResults(elements, after, ticksToSeconds)` (#609 dropped the `before` snapshot arg) diffs each edge against the LIVE element's current `startTick`/`endTick` rather than a pre-drag snapshot, closing a one-frame skipped-write window under reordered drags (the math's input snapshot can be ordered differently than the live sorted children mid-drag, so a snapshot-vs-snapshot diff could compare the wrong pair and skip a write the live values still needed). A changed edge gets a SINGLE write pass (rounds the tick, sets `startTick`/`endTick`, AND re-derives `start`/`end` from the same rounded tick in one shot) so the tick attribute and its seconds cache never observably disagree between writes, even transiently. The seconds-only sibling `applyBoundaryResults(elements, after)` dropped the same `before` arg for the same live-diff reason. A seconds-based neighbor pulled into tick-space link/collision math (via `tickSpaceData`) gets seconds back in its own authoritative unit and never gains tick attributes.

**Visual elements (Shadow DOM):**

- `<daw-waveform>` — Chunked canvas rendering (1000px chunks; bars straddling a chunk boundary are marked dirty on BOTH chunks and drawn by the next chunk at a negative local x — `barWidth+barGap` rarely divides 1000). Receives peaks as JS properties. Uses dirty pixel tracking for incremental rendering — `updatePeaks(startIndex, endIndex)` marks a range dirty without full redraw. Bits derived from typed array (Int8Array→8, Int16Array→16). Drawing batched via `requestAnimationFrame`.
- `<daw-playhead>` — Pure visual element; exposes `setPosition(px)`. The editor's `PlaybackAnimationController` drives it each frame (single RAF loop that also dispatches `daw-timeupdate`).
- `<daw-ruler>` — Temporal time scale with tick marks. Ported from `SmartScale` (temporal mode only, beats & bars deferred). Computes ticks once in `willUpdate()`, reused by both `render()` and `updated()`.

**Control elements:**

- `<daw-editor>` — Core orchestrator. Owns an arrangement from construction and builds its engine on it once it is connected with an adapter; enters each `<daw-track>` into the arrangement, which loads its audio; renders waveforms from peaks.
- `<daw-transport for="editor-id">` — Container that resolves target via `document.getElementById`. Light DOM.
- `<daw-play-button>`, `<daw-pause-button>`, `<daw-stop-button>` — Walk up to closest `<daw-transport>` for target resolution. Warn when target is null.
- `<daw-record-button>` — Transport button. Start-only: calls `startRecording()` on the target editor (stop belongs to the stop button). Listens for `daw-recording-start`/`daw-recording-complete` events to update visual state.
- `<daw-player>` — Lightweight single-track HTMLMediaElement player (epic #454, core implemented in #473). Wraps `MediaElementPlayout` — no Tone.js, no PlaylistEngine. Attributes: `src`, `peaks-src` (pre-computed BBC audiowaveform `.dat`/`.json`), `wave-height`, `timescale`, `mono`, `bar-width`, `bar-gap`, `rounded-bars`, `playback-rate`. Scrubber fallback when `peaks-src` is omitted. Fit-to-width waveform; click-to-seek. Properties: `isPlaying`, `currentTime`, `duration`, `volume`, `audioElement`. Methods: `play()`, `pause()`, `stop()`, `seekTo(s)`, `setPlaybackRate(r)`, `setVolume(v)`. Events: `daw-ready`, `daw-play`, `daw-pause`, `daw-stop`, `daw-timeupdate` (`{ time }`), `daw-ended`, `daw-error` (`{ operation, error }`). Follow-up issues: effects (#475), `<daw-playback-rate>` element (#476), transport-compat tests (#474), annotations (#477).
  - **`daw-ready` re-arm spans BOTH `src` and `peaks-src`** — `daw-ready` is gated on metadata loaded + peaks settled. Reset `_metadataLoaded`/`_readyDispatched` in `_loadSource()` (on `src`) AND `_peaksSettled`/`_readyDispatched` in `_loadPeaks()` (on `peaks-src`). Resetting on only one input is a bug: a `src`-only swap never re-fires `daw-ready`, and a `src`+`peaks-src` swap can fire on STALE metadata if the small `.dat` resolves before the new `loadedmetadata`. General rule: a readiness event gated on N async inputs must re-arm on every input that starts a new cycle. The STALE guard (`peaksSrc !== requested`) must cover the catch too — a superseded load's late rejection settling readiness fires `daw-ready` on stale state. A THIRD re-arm trigger: disconnect→reconnect rebuilds the engine and reloads the source, so a reparented player fires `daw-ready` again (it is a new load cycle).
  - **Dispose-on-disconnect / rebuild-on-reconnect lifecycle** — `disconnectedCallback` disposes the `MediaElementPlayout` (a removed player must not keep audio alive); `connectedCallback` rebuilds the engine and reloads `src` when it was disposed (reparenting disconnects+reconnects synchronously — without the rebuild the player is dead forever). Only VOLUME is preserved across the rebuild; position and metadata reset (the playhead is snapped to 0 to match).
- `<daw-time-display>` — Formatted playback time readout. Document-level `daw-timeupdate`/`daw-time-format-change` listeners filtered by `e.target === transport target` (tolerates late-upgrading targets; re-resolves per event). `role="status"`, `aria-live="off"`.
- `<daw-time-format>` — Select that sets format ON the target (`target.setTimeFormat()`); target owns the state, all controls sync via the bubbled `daw-time-format-change` event (native-form style). Use this target-owned-state pattern for future transport inputs (#463 selection inputs, tempo, etc.).
- **Transport capability detection (`utils/transport-capability.ts`)** — Button subclasses declare `static requiredTargetMethods`; non-button controls call `targetSupports()` directly. Benefit of the doubt: a missing or not-yet-upgraded custom-element target counts as supported (control stays ENABLED; click-time resolution warns via `warnNoTargetOnce`) — only a _defined_ target lacking the methods renders disabled. `pointerenter` triggers `requestUpdate()` so late targets re-evaluate before the click. Warn dedup is per element per message (`warnOnce`).
- **One playback RAF loop** — `PlaybackAnimationController` on the editor is the only per-frame playback loop (positions playhead + dispatches `daw-timeupdate`). Never add a second RAF loop for playback-time concerns; consume `daw-timeupdate` instead.
- **Seek-while-playing settle suppression** — `seekTo`/pointer-handler set `_inSeekTransition` around the internal `stop()` so the transient engine-stop settle (which rewinds to play-start) doesn't leak a backward-jumping `daw-timeupdate`. Any new stop-adjacent code path must do the same.

## Track Controls

- **`<daw-track-controls>`** — Shadow DOM element. Receives track state as props from editor (the mix from `_mixOf`, below), dispatches `daw-track-control` `{ trackId, prop, value, gesture? }` and `daw-track-remove` events. During a take the `muted` prop of the track it records onto is true: `_mixOf` reads `engine.getState().tracks`, which reports that track muted (see `notes/recording.md`, "The take's mute"). Its `recording` prop (the editor passes `engine.recordingTrackIds.has(trackId)`, re-read on every render, which the engine's statechange after `setTrackRecording` triggers) disables the M button and makes `_onMuteClick` a no-op: a click would send `muted: false`, a no-op or a silent unmute of the stored mute while the button shows on (parity with React's `<TrackMuteButton />`). Tests: `daw-track-controls.test.ts`, `daw-editor-recording-mute.test.ts`.
- **Controls outside the scroll container** — fixed-width `.controls-viewport` (180px, `--daw-controls-width`, `overflow: hidden`) wraps `.controls-column`, which mirrors `.scroll-area`'s `scrollTop` via transform. Controls stay pinned horizontally while waveforms scroll x, and stay row-locked while the editor scrolls y.
- **The controls draw the arrangement's mix (#843)** — `_mixOf(trackId)` is the one reader: `mixOf(arrangement, id)` (`interactions/arrangement-view.ts`: the arrangement's `getMixer()`, muted while `recordingTrackIds` has the track, as the engine plays it), else for a track still waiting for the adapter what its element declares. The editor holds no mix (#848); `editor.tracks` fills the four fields from `_mixOf`.
- **Direct arrangement forwarding** — the `daw-track-control` handler calls the arrangement's setter directly (#848: a loading track is in the arrangement too), with `{ gesture }` when the detail has one. Does not go through `<daw-track>` DOM element roundtrip (file-dropped tracks have no DOM element).
- **A slider drag is one undo step (#843)** — `<daw-track-controls>` holds one `createMixerGesture()` (core) per slider as a class field, attaches each to its range input (`.vol-row input`, `.pan-row input`) in `firstUpdated`, detaches both in `disconnectedCallback` and attaches again in `connectedCallback` when `hasUpdated` (a moved element keeps its shadow root and inputs). The volume and pan events carry `gesture: <that slider's id>` in the `daw-track-control` detail (`DawTrackControlDetail.gesture`); mute and solo send none, so each click is a step. The gesture ends on the input's native `change` (end of a pointer drag), the `keyup` of a held range key, or `blur`. Tests: `daw-track-controls.test.ts` "slider gestures (#843)", `daw-editor-mixer-undo.test.ts` "control gestures (#843)".
- **Track ID alignment** — `buildArrangementTrack` gives the arrangement track the editor's `trackId` and each clip its `<daw-clip>.clipId` (or a generated id written back into a drop descriptor), so `editor.removeClip` / `updateClip` and the mixer setters find them by id.
- **`track-reordering` attribute + `reorderable`/`trackIndex`/`trackCount` props (#612)** — `<daw-editor track-reordering>` mirrors into `reorderable` on each `<daw-track-controls>` it renders; `trackIndex`/`trackCount` drive the move-button disabled state (up disabled at index 0, down disabled at the last index). See `reorderTrack()`, `TrackReorderHandler`, and "The arrangement's order is drawn; the DOM order is a request" in `notes/interactions.md`.
- **`TrackReorderHandler` waveform-lane mirroring (drag-preview parity with React)** — On grab, it snapshots the shadow timeline's `.track-row` lanes by `data-track-id` (`this._lanes`, aligned index-for-index with the controls `_rows`) in addition to the controls rows it already tracked. On every `pointermove` it mirrors the same shift onto both: displaced lanes translate by the dragged lane's height, and the dragged lane slot-snaps to the target's rect top (not a pixel-follow like the dragged controls row). Transform-only — lane DOM order never changes; the drop is one `reorderTrack` call (#848: the arrangement's order, no element moved). The dragged lane gets `data-track-drag-source` + `z-index: 10` + `position: relative`; both rows and lanes get an inline `transition: transform 150ms ease` (skipped under `prefers-reduced-motion`, matching the React side's `useTrailingActive` gate). `_cleanup()` (pointerup, pointercancel, AND the editor's disconnect-mid-drag `cancel()`) clears all inline styles and the `data-track-drag-source` attribute on every tracked lane, so an interrupted drag never leaves a stray attribute or offset behind. Styling hook: `.track-row[data-track-drag-source]` in `elements/daw-editor.ts`'s CSS uses the same tint as `.track-row.selected` (`rgba(99, 199, 95, 0.08)`).
- **A file drop is an element-less track (#848)** — `file-loader.ts` adds each dropped file through `_addDroppedFile`: a track whose one loading clip's source is the `File` (a File cannot be an attribute), entered through the queue like any track, reorderable and undoable. A file that fails is removed with `{ undoable: false }`. (From #612 to #848 drops were real `<daw-track><daw-clip>` elements loaded from blob URLs.)

## Empty State

- Hide playhead, selection, and ruler when `orderedTracks.length === 0`
- Timeline width: `100%` when empty (not hardcoded pixels) for full-width dropzone
- `.scroll-area` has `min-height: var(--daw-min-height, 200px)` for visible empty dropzone
- **`fill-viewport` attribute (layout)** — when set (or when `indefinite-playback` is set, which implies it), `_totalWidth` floors at `_viewport.containerWidth` so the ruler renders the visible viewport even with no clips. `daw-ruler` covers `max(naturalDuration, totalWidthDerivedDuration)` so it doesn't shrink when a short clip is added. Editor renders an empty controls-column placeholder so the timeline doesn't shift right when the first track loads. `ViewportController` has a `ResizeObserver` for window-resize support. Parity with the React provider's `fillViewport` prop.
- **End-of-timeline auto-stop (behavior, parity with React #589/#590/#593)** — by default the frame loop in `_startPlayhead` auto-stops playback when raw engine time reaches `_duration` (engine stop rewinds to play-start; `daw-stop` fires). `indefinite-playback` opts out (DAW-style roll until explicit stop); an active recording session (`this.isRecording`) suppresses it so overdub takes run past existing material. `AnimationController.start`'s loop checks `_callback !== null` before rescheduling — an in-frame `stop()` (the auto-stop path) must not leave a zombie rAF loop.
- **No `daw-timeupdate` may follow `daw-stop` in the auto-stop frame** — `PlaybackAnimationController.start`'s wrapper re-checks `_running` after `getTime()` returns (an in-frame auto-stop sets it false) before `setPosition`/dispatch; without the guard, one trailing timeupdate with the rewound position fires AFTER `daw-stop` and corrupts stop-cleared consumer state (e.g. the annotation playing highlight). The manual-stop settle timeupdate dispatches from `_stopPlayhead` (outside the wrapper) and is intentional — don't guard that path.
- **Engine-initiated bounded-playback stop also dispatches `daw-stop` (#608 follow-up)** — the engine's `onPlaybackEnded` hook (Tone adapter, and since #636 the native adapter too, reporting a duration-limited `play(start, end)` self-terminated; the native transport's timer runs in a Worker, so the editor's rAF loop can no longer be assumed to observe `time >= endTime` before the transport's own self-stop) calls `PlaylistEngine.stop()` from its OWN queued microtask, bypassing `editor.stop()` entirely. The editor's engine `'stop'` handler dispatches `daw-stop` for exactly this case — guarded by `!_inConsumerStop && !_inSeekTransition` so it never double-fires for `editor.stop()` (which dispatches its own, bracketing the engine call with `_inConsumerStop`) or the seek-adjacent stop+reschedule paths (guarded by `_inSeekTransition`, which intentionally suppress the settle). The rAF end-of-timeline/bounded-playback watchdog in `_startPlayhead` is a separate mechanism — it calls the public `editor.stop()`, so it's already covered by the `_inConsumerStop` path.

## Spectrogram

- **`render-mode="spectrogram"`** — one of the `RenderMode` variants (`'waveform' | 'spectrogram' | 'both'`) shared with core via the `TrackRenderMode` alias (see the `TrackRenderMode` bullet earlier in this file). `<daw-track render-mode="spectrogram">` switches that track's rendering branch in `<daw-editor>`'s template to emit one `<daw-spectrogram>` per channel instead of `<daw-waveform>`. `'both'` currently warns + falls back to `'spectrogram'`.
- **`<daw-spectrogram>`** — Shadow DOM, 1000px chunked canvases. Each canvas is transferred via `transferControlToOffscreen()` and handed up to the editor via `editor._spectrogramRegisterCanvas(...)`. Lives inside the editor's shadow root; uses `getRootNode().host` to find the editor (see "Elements Inside `<daw-editor>`'s Shadow DOM Use `getRootNode().host`, Not `closest()`" later in this file for the rationale).
- **`SpectrogramController`** — Lit reactive controller on `<daw-editor>`. Built lazily on first `registerCanvas`; disposed when no spectrogram tracks remain (`_disposeSpectrogramControllerIfEmpty`). Holds editor-level defaults + per-track overrides separately and merges them down to one `(config, colorMap)` pair for the orchestrator (v1 limitation: orchestrator accepts a single config/colorMap at a time; first track override wins).
- **`editor.spectrogramConfig` + `editor.spectrogramColorMap`** — editor-level defaults. Separate properties because `ColorMapValue` is not a field on `SpectrogramConfig`. Both setters forward to the controller and `requestUpdate()`.
- **`track.spectrogramConfig`** (on `<daw-track>`) — per-track override. Reflected through `daw-track-update` like the other track props.
- **`daw-spectrogram-ready` event** — fired (bubbles + composed) when the viewport tier completes for a track. Re-dispatched from the orchestrator's `viewport-ready` by the controller. Typed in `DawEventMap`.
- **`_maybeRegisterSpectrogramClipAudio(trackId, clip)` reads `clip.audioBuffer` directly** — see "Read `clip.audioBuffer` Directly in Helpers Called During Concurrent Track Loading" later in this file for the full rationale.
- **Worker URL** — `new URL('@dawcore/spectrogram/worker/spectrogram.worker', import.meta.url)` inside `_ensureSpectrogramController`. Bundler must support package-relative URL resolution (Vite does).

## `<daw-keyboard-shortcuts>` Must Be Inside `<daw-editor>`

Resolves its parent via `closest('daw-editor')`. Placing it as a sibling (e.g. inside `<daw-transport>`) silently fails — runtime warns "Preset shortcuts will be inactive; only customShortcuts will fire." Easy to miss because transport buttons in `<daw-transport>` work via id-based lookup, suggesting both should.

## Elements Inside `<daw-editor>`'s Shadow DOM Use `getRootNode().host`, Not `closest()`

`closest(selector)` does NOT cross shadow boundaries. Elements rendered inside `<daw-editor>`'s shadow root (e.g. `<daw-spectrogram>`, `<daw-waveform>`, `<daw-piano-roll>`) cannot find the editor via `this.closest('daw-editor')` — it returns `null`. Use `(this.getRootNode() as ShadowRoot).host`, optionally falling back to `host.closest('daw-editor')` for deeper shadow nesting. `<daw-spectrogram>._findHostEditor()` is the reference implementation. Light-DOM children of `<daw-editor>` (like `<daw-keyboard-shortcuts>`) CAN use `closest('daw-editor')` since they're not inside a shadow root.

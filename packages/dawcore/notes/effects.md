# The effects chain

Notes of dawcore Package (`@dawcore/components`), moved out of the package's `CLAUDE.md`. Read before changing the effects chain, WAM or Faust hosting from the editor.

## Effects Chain (core, #417)

- **`src/effects/`** — `EffectsChainController` (ordered chain between owned input/output gains) + effect registry (the registry itself, `registerEffect`/`getEffectDefinitions`/`prepareEffect`/`createEffectInstance` and the definition types, lives in `@waveform-playlist/core` since #679 and is shared with the React hooks; dawcore does NOT export it, and `effect-registry.ts` here only registers the `native-*` built-ins on import (each marked `builtIn: true` so the React effect picker, which reads the same registry, does not list them; and only if the name is not already registered), so any module that needs them present imports it for the side effect; `native-*` built-ins — gain, compressor, stereo-panner, delay, plus one type per biquad shape (`native-filter` = lowpass, `native-highpass`/`bandpass`/`notch`/`peaking`/`lowshelf`/`highshelf`, #661; table-driven via `BIQUAD_FILTERS`, each exposing only the params its shape uses; **Web Audio's `Q` is resonance in dB for lowpass/highpass and a linear quality factor for bandpass/notch/peaking** — `native-highpass` has its own dB-typed `q` def defaulting to −3 (flat Butterworth), while `native-filter` keeps its original linear-looking range untouched for persisted-chain compatibility)) + `EffectsManager` (per-editor chain ownership/wiring/events).
- **WAM entries (#422)** — `addWamPlugin(url, initialState?)` on both elements (async). Dynamic-imports the optional `@dawcore/wam` peer (install-hint rethrow, midi-loader pattern), `ensureWamHost` → `createWamInstance` → chain entry `{kind:'wam', type:'wam', url, label: descriptor.name}` whose instance wraps the plugin's audioNode (input=output=node, `applyParams` → `setParameterValues` map, `dispose` → `plugin.destroy()`). All chain ops are kind-agnostic — remove destroys the worklet, bypass = disconnection (no wet param). Mock `@dawcore/wam` in tests with `vi.hoisted` + `vi.mock`; the missing-package path needs its own test FILE (a throwing `vi.mock` factory is file-scoped).
- **Faust entries (#430)** — `addFaustEffect(dspCode, {name?})` on both elements (async). Dynamic-imports the optional `@dawcore/faust` peer (same install-hint pattern), compiles BEFORE any chain work (a Faust error — diagnostics intact — leaves the chain untouched), then `ensureWamHost` → `createWamInstanceFromFactory(compiled.factory, …, {label: compiled.name})` → the shared `_insertWamPlugin` helper (also used by `_addWamToChain`). Entries are `kind:'wam'` with `source:{faust: dspCode}` and NO url; `daw-effect-add`/`daw-effect-error` details carry `source` instead of `url`. Persistence serializes `{kind:'wam', faustDsp, faustName: label, bypassed, state?}`; restore and offline export RECOMPILE (slow path, accepted); failed recompiles become placeholders that round-trip `faustDsp`. `validateSerializedEntries` accepts wam entries with `url` OR `faustDsp`. Tests mock `@dawcore/faust` like `@dawcore/wam` (`daw-editor-faust.test.ts`; missing-package file: `daw-editor-faust-missing.test.ts`).
- **Element API (#418; per-track-by-id #522)** — master-chain methods on `<daw-editor>` (`addEffect`/`removeEffect`/`setEffectParams`/`setEffectBypassed`/`moveEffect`/`effects`, plus `addWamPlugin`/`addFaustEffect`/`open`/`closeEffectGui`/`get`/`setEffectsState`). The SAME surface keyed by trackId also lives on `<daw-editor>` — `addTrackEffect`/`removeTrackEffect`/`setTrackEffectParams`/`setTrackEffectBypassed`/`moveTrackEffect`/`trackEffects`/`addTrackWamPlugin`/`addTrackFaustEffect`/`open`/`closeTrackEffectGui`/`get`/`setTrackEffectsState` — so element-less tracks (file-dropped, programmatic) get their own chain. `<daw-track>` element methods are thin sugar over these (`track.addEffect(t)` === `editor.addTrackEffect(track.trackId, t)`); the structural `TrackEffectsDelegate` in daw-track.ts mirrors that PUBLIC surface (NO more `_track*` internals — removed #522; avoids a value-import cycle). Per-track `daw-effect-*` events dispatch from the `<daw-track>` element when one exists (resolved via `_trackEventTarget(trackId)`), else from the editor; master events from the editor. Typed in `DawEventMap`.
- **Effect GUIs (#423)** — `openEffectGui(effectId, container)`/`closeEffectGui(effectId)` on both elements (track delegates to the editor's public `openTrackEffectGui`/`closeTrackEffectGui`). Host-agnostic: the consumer provides the container. GUI lifecycle lives in `EffectsManager` (`_guis` cache + `_guiPending` in-flight dedup, keyed by globally-unique effectId): **lazy create on first open, close = detach-but-cache, destroyGui only on removal** — but generic FALLBACK panels rebuild on reopen (they bake slider values at build time; an API-side `setEffectParams` while closed would show stale values and the first drag would snap the audio back). Plugin-provided `createGui` elements stay cached across close/reopen (`_runOp` remove / `disposeTrackChain` / `disposeAll` — destroy GUIs from `chain.entries` BEFORE `chain.dispose()`). WAM entries carry optional `createGui`/`destroyGui`/`getParameterInfo` on the `EffectInstance` closure; `EffectsChainController.getEntry(effectId)` exposes the live entry (incl. instance) to the manager. Fallback when no `createGui` (or it throws, or it resolves with something that is not an `HTMLElement`, or `kind:'native'`) — **the WAM SDK's base `WebAudioModule.createGui()` exists on EVERY plugin and resolves `undefined` when the plugin ships no GUI module**, so "has a createGui function" does not mean "has a GUI" (a Faust WAM built without faust-ui hit this: `appendChild(undefined)` threw and no panel appeared; found by a real-browser page test, #677 — the unit mocks only ever modelled a missing function or a throwing one): the generic panel from `@dawcore/wam` (dynamic import, install-hint rethrow via shared `_loadWamModule(feature)`) — native entries map the registry definition's `params` + current values, WAM entries proxy `getParameterInfo`; **panel edits route through `_runOp setParams`** so they hit applyParams→setParameterValues AND dispatch `daw-effect-change` like API edits. An effect removed while its GUI is mid-create: the open rejects and the late GUI is destroyed (post-await re-check of `chain.getEntry`). Error placeholders refuse to open. Close on a never-opened id warns, never throws.
- **Persistence (#424)** — `getEffectsState()`/`setEffectsState()` on both elements. `SerializedEffectEntry` union (native: type+params+bypassed; wam: url+bypassed+state). Restore is sequential (order survives async WAM loads); a failed WAM url becomes a **bypassed passthrough placeholder** at its position carrying `error` + `placeholder: {state, bypassed}` so re-serialization round-trips the saved state — `daw-effect-error` fires, restore continues. **Failed NATIVE entries get the same policy** (unregistered custom type → passthrough placeholder carrying the saved params/bypassed, `daw-effect-error` with `type`, restore continues — the old chain is already destroyed at that point, so throwing would strand a half-built chain). Serialized placeholder entries carry `placeholder: true` so offline export can skip them; restore ignores the flag and retries normally. `setEffectsState` validates the whole array BEFORE clearing the chain (shape only — registry membership is a runtime concern handled by the placeholder path).
- **Offline export (#426)** — `editor.exportAudio({sampleRate?, startTime?, duration?, channels?})` renders through all chains on an `OfflineAudioContext`. No Transport involved: clips are scheduled statically (`source.start(when, offset, duration)` with window clamping at both edges). Chains rebuild from their PERSISTED form (getEffectsState): natives via the registry (BaseAudioContext definitions), WAM via `ensureWamHost(offlineCtx)` + re-instantiation with saved state — worklets are context-bound (wam-studio cloneInto pattern; `cloneInstanceInto` in @dawcore/wam). All offline plugin instances destroyed in `finally`. Bypass parity: wet-zeroed natives created with wet 0; disconnect-bypassed entries skipped; failed-plugin placeholders skipped via the serialized `placeholder: true` marker REGARDLESS of their saved bypassed flag (live playback silently skips them — instantiating would fail the export or render an effect absent from what the user hears). Track order is clips → chain → volume → pan (pre-fader, #660); master volume (engine `setMasterVolume`) feeds the master chain, as live. Clip fades are NOT rendered — parity with native ClipPlayer, which doesn't apply them either. Logic in `interactions/export-audio.ts` (ExportAudioHost interface); the editor method is a thin wrapper. **Pan (#669):** each track is panned by core's `createPanStage(ctx, track.pan, trackPanLaw(track))`, where the host's tracks (`_loadedTracks()`, `loadedTrack` in `interactions/arrangement-view.ts`) carry the arrangement's `panLaw` (#684) — the same stage and law as the live `TrackNode`, never a `StereoPannerNode` (whose law would follow the chain's output layout). Live-vs-export RMS difference measured at exactly 0 for mono/stereo clips × three pans × with/without a stereo-output effect.
- **Wiring** — chains are created lazily on first addEffect and wired via the adapter transport's hooks: track chains are PRE-FADER inserts (#660) — `connectTrackEffects(trackId, chain.input, chain.output)` hands BOTH ends to the transport, which returns the output into the track ahead of volume/pan/mute (never connect a track chain's output to `masterOutputNode`: that bypasses the fader, pan, mute and solo, and was the pre-#660 post-fader wiring); master chain `connectMasterOutput(chain.input)` + `chain.output → ctx.destination`. Adapters without `transport.connectTrackEffects` get a clear throw — and one that still has the old `connectTrackOutput` gets an upgrade hint (`@dawcore/transport` >= 0.0.16 / `@waveform-playlist/playout` >= 13). **Transport `setTracks` rebuilds TrackNodes and severs hookups** — the editor's statechange handler calls `rewireTrackChains()` on every `tracksVersion` bump (the transport releases the old return edge itself). Track removal → `disposeTrackChain`; editor disconnect → `disposeAll`. `exportAudioImpl` mirrors the order offline: clip → clip gain → chain → volume → panner → master volume → master chain.
- **Entries are kind-agnostic** — chain operations never branch on `kind` (`'native' | 'wam' | ...`). New plugin standards wrap their node into `EffectChainItem` and get move/remove/bypass/events for free.
- **Topology rebuilds, params never** — `setParams` calls the instance's `applyParams` in place. Rebuilds sever ONLY the chain's own outgoing edges (`input.disconnect()` + each entry's `output.disconnect()`) — never the consumer's edges into `input` / out of `output`.
- **Bypass is two-mode** — definitions with `wetParam` bypass by zeroing wet (stored/restored, no rebuild); others are removed from the series with the instance kept alive at its position. `setParams` on a bypassed wet effect stores the new wet without making it audible.
- **Registry definitions take `BaseAudioContext`** — same definitions must serve offline rendering (#426). Don't add `AudioContext`-only API usage to built-ins.
- **`NativeEffectDefinition.prepare` (#657; the type is in core)** — optional async per-context setup (AudioWorklet `addModule`). `prepareEffect(type, ctx)` in the registry memoizes per context in a `WeakMap<BaseAudioContext, Map<type, record>>` keyed by the definition object too (re-registering re-prepares; failures evict; a sync throw becomes a rejection). Awaited by `buildOfflineChain` (every export has a fresh context → runs again; a disconnect-bypassed entry is skipped BEFORE preparing) and by `_restoreChain` (failure → the native placeholder path; re-check `superseded()`/`chain.disposed` after the await). Both go through `ensureEffectPrepared` (loops until the CURRENT definition is prepared — a type re-registered mid-await would otherwise reach `create` unprepared) and **`_restoreChain` only awaits when `needsPrepare()` says so**: an unconditional await made every native restore async, so `setEffectsState(x); addEffect(y)` put `y` first and `effects` read empty right after the call. The sync `addEffect` path cannot await: `editor.prepareEffect(type)` is the consumer's step, and `createEffectInstance` rewraps a `create` throw with that hint ONLY when the type has a hook that hasn't settled on that context (otherwise the original error object propagates untouched). Any new code path that calls `createEffectInstance` on a context must decide which of those two it is.
- **Registry tests** — call `_resetEffectRegistryForTests()` (from `effects/effect-registry`) in `beforeEach`: it unregisters everything from core's registry and re-registers the built-ins. Registry functions are imported from `@waveform-playlist/core`, which tests resolve through its `dist`: rebuild core after changing the registry. Test-only helpers are exported from their module but NOT from `src/index.ts`.
